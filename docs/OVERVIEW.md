# LitBench 概览

> 一个跑在自己机器上的 PDF 文献工作台：把「读一篇论文」拆成能复查的步骤 —— 定位、精读、翻译、看图、拆论证、跨文档对照。

LitBench 不是一个把 PDF 丢给模型、吐一段总结的玩具。它的前提是：**PDF 的样子要原样保留，AI 的分析要能落回原文的具体位置，所有数据留在你自己的磁盘上。**

---

## 一、它解决的问题

读文献真正耗时间的不是「读完」，而是这几件事反复打断你：

- 一篇几十页的论文，想快速判断值不值得读，却要自己翻摘要、图、结论；
- 英文文献读得慢，跳过一段又怕漏掉关键限定条件；
- 图看了半天，不知道作者想让它证明什么；
- 正文、Supporting Information、审稿意见散在三个 PDF 里，对不上；
- 读完写笔记，过两周只记得「好像有个反例」，找不到在哪一页。

LitBench 把这些都做成了**带页码、可跳回原文**的操作，而不是一次性的对话输出。

## 二、功能地图

界面分三层：左边是库与导航，中间是原文，右边是 AI 面板。

### 1. 文献库

- 拖拽 PDF 进窗口即入库，也可以粘贴 arXiv 之类的链接导入；
- **分区**（collections）自由新建，像文件夹一样组织课题；
- **标签**跨分区检索，速读抽出的关键词可以一键存成标签；
- **角色**给每篇打标：正文 / SI 支撑材料 / 审稿意见 / 其他 —— 这是「跨文档综合」的依据；
- 阅读状态（未读 / 在读 / 已读）与进度百分比，一眼看出欠了多少账；
- `Ctrl + K` 全库全文搜索，命中的是正文文本，不只是标题。

### 2. 阅读器

- pdf.js 逐页 canvas 渲染，再叠一层自建文本层 —— **排版、字体、公式、双栏、插图都是原样**，不是转成文本重新排版；
- **目录自动抽取**：按字号、加粗、章节编号、字母占比猜层级，双栏论文用「行级 Otsu 找栏切点」避免左右栏缝成一句；
- 缩略图快速定位，目录点击跳转；
- 25%–400% 缩放、适宽 / 整页、页码输入跳转；
- 页内查找，`当前/总数` 步进，比浏览器自带的 Ctrl+F 准（文本层坐标是自己算的）。

### 3. 标注：选中就有三个选择

在任何位置选中文字，浮出三个按钮：

| 按钮 | 行为 |
| --- | --- |
| **高亮** | 5 种颜色，按页持久化；点高亮可以闪一下跳回原位 |
| **笔记** | 引用原文 + 写自己的批注，进笔记面板可导出 |
| **提问** | 把原文塞进对话的上下文，预填「请解释这段话，并说明它在本文论证中的作用」 |

提示语言跟随界面语言：界面切英文，预填的 prompt 也变英文。

### 4. 右栏六个面板

| 面板 | 你得到什么 |
| --- | --- |
| **速读** | 一句话概括、核心贡献、方法、结论、局限、关键词；关键词一键变标签 |
| **翻译** | 逐段英译中；「双语对照」或「仅译文」；当前页或全篇；40 段一批渐进加载，译文逐段落库，下次打开还在 |
| **图表** | 按 caption 自动切图区，也可以自己框选截图；视觉模型给出图题、要点、注意事项；点图跳回原页 |
| **结构** | 论证树：论点 → 前提 / 证据 / 推理 / 结论 / 反例，分层折叠，每个节点带原文引文与页码，可导出 |
| **笔记** | 全部高亮与批注的清单，按篇/按页筛，导出 Markdown |
| **会话** | 针对全文或选中段落问答，SSE 流式输出，回答里的页码可点击跳转 |

还有一层隐藏的联动：**跨文档综合**。给同一课题的文献打上「正文 / SI / 审稿意见」角色后，可以让模型把三者放在一起读，输出摘要、互相印证之处、矛盾与张力、SI 提供的额外细节、审稿人的质疑 —— 这是单个 PDF 阅读器给不了的东西。

## 三、特色

**1. 本地优先，AI 走你自己的端点**

服务只绑 `127.0.0.1`，PDF、文本、标注、对话历史都在本地数据目录。AI 请求发往你填的任意 OpenAI 兼容端点，模型和 Key 自己控。没有账号、没有云端同步、没有隐藏上传。

**2. 渲染保真，而不是「转文本」**

很多工具先把 PDF 抽成纯文本再交给模型，双栏会串行、公式会散架、图直接消失。LitBench 是 canvas 原样画出来，文本层只负责选区和定位。你看的和模型读的，是同一份纸。

**3. 坐标不漂**

所有标注以 `scale = 1` 的坐标系存，渲染时乘缩放比。所以 400% 和高亮位置对得上，关掉重开也对得上 —— 这是自建文本层换来的。

**4. 双栏感知的抽取**

「行内 gap 断行 + 行级 Otsu 找栏切点 + 整栏成块输出」，这组启发式是按真论文调出来的。它决定了目录、段落、翻译分块的质量，也是为什么有些工具翻译出来是乱序的。

**5. 零构建、零数据库**

前端是原生 ES module，服务端是一个零依赖的 `server.js`。没有 webpack、没有 Postgres、没有迁移脚本。每篇论文一个 state JSON，900ms 防抖保存，关阅读器时强制 flush。

**6. 增量生成，不怕中断**

翻译、结构树、综合都是边生成边落库。模型中途挂了，已出来的部分不会白跑；换个模型接着做也行（面板头部可以逐任务切换模型，选择按文献记住）。

**7. 能作为 DeepSeek Harness 插件跑**

`plugin/` 是标准的 DSH 插件包：随宿主启动、不额外占端口，会话头部加一个「文献工作台」按钮，点开全屏。也可以用独立窗口打开，当普通网页用。

## 四、使用方式

### 5 分钟上手

```bash
cd litbench
npm start          # 或双击 start.bat，默认 http://127.0.0.1:8788
```

打开页面 → 右上角齿轮 → 填三样：

1. **接口地址**：任意 OpenAI 兼容的 `/v1` 端点；
2. **文本模型 / 视觉模型**：填端点上的模型 id（可下拉可手填，不同网关都能用）；
3. **API Key**。

保存后拖一个 PDF 进窗口就行。默认数据落在仓库下的 `data/`，可在设置里改到别的盘并顺带迁移。

> **已经在用 DeepSeek Harness？** 工作台会自己去读 `~/.dsh` 里当前的模型配置（供应商、接口地址、Key、模型列表），打开就是能用的状态，上面那三步可以跳过。检测不到才用通用默认值。
>
> **地址记不住？** DSH 每次重启监听的端口都会变，插件入口地址跟着变。想有个固定入口就把工作台当成独立服务常驻在 <http://127.0.0.1:8788/>（`start.bat` 或 `npm start`），浏览器收藏这个地址即可，与 DSH 重启无关。

> 图表解读需要 vision 模型；全篇 JSON 类任务（速读 / 结构 / 综合）建议用长输出稳定、不开 reasoning 的模型 —— reasoning 模型容易把预算吃在思维链上，正文返回空。

### 三层阅读法

**第一层，扫。** 打开就点「速读」，同时看目录和缩略图。三十秒决定这篇是「待读」还是「放弃」。有用的关键词顺手存成标签。

**第二层，读。** 中间读原文，遇到读不顺的段落选中 → 翻译面板；遇到关键句选中 → 高亮或记笔记；看不懂就问，选中文字后「提问」，原文会自动进上下文。

**第三层，拆。** 读完整篇点「结构」，看模型把论证拆成什么样，再回头对照原文 —— 它给每个节点都标了页码，可以直接去核对。这一步最容易被模型带偏，所以一定要跳回去看。

### 典型场景

**写综述，一堆 PDF 怎么管。** 按课题建分区，正文/SI/审稿意见用角色区分。单篇的结构树导出成 Markdown 攒素材；几篇同主题的走「综合」，重点看它找出的**矛盾点** —— 那是综述里最有价值的部分。

**读一篇带 SI 的化学/材料论文。** 正文和 SI 都入库，角色分别标注，然后用综合面板问「SI 里有哪些正文没提的实验条件」。比自己在两个 PDF 之间来回翻快得多。

**英文文献读不快。** 翻译面板切「双语对照」，按页翻，一次 40 段。不求全篇翻完，先翻正在读的那几页。

**图和公式。** 图走图表面板（自动切图 + 视觉解读），公式别指望文本层，看 canvas 就行 —— 这也是不转文本的原因。

### 数据与备份

- 数据目录：`LITBENCH_DATA` > `~/.litbench/home.json` > 仓库下 `data/`；
- 里面是 `papers.json`（库）、`pdfs/`、`states/`（每篇的标注与 AI 结果）、`texts/`（抽好的正文）；
- 备份整个目录即可，换机器拷过去能用；
- 抽取出错（目录空、段落乱）时，删掉该篇 state 里的 `sections/paragraphs/figures/extracted` 再打开会重抽。

## 五、它不做什么

- 不做云端同步、不做多人协作 —— 这是刻意的，文献不该离开你的机器；
- 不替代精读 —— 所有 AI 结论都带页码，是给你去核对的，不是给你抄的；
- 不做文献管理器的全部功能（引文格式、BibTeX 导出目前没有）；
- 不保证任何模型都表现好 —— 长 JSON 任务对模型有要求，见上面的模型建议。

## 六、技术一览（给想改的人）

```
server.js        零依赖 HTTP 服务：入库、Range 读流、state 存取、全文检索、SSE 转发
public/js/core.js       i18n / api / store / markdown / toast / streamChat
public/js/app.js        文献库、路由、搜索、上传、分区、设置
public/js/reader.js     canvas 渲染 + 文本层 + 目录抽取 + 标注 + 查找
public/js/insights.js   右栏 AI 面板（速读/翻译/图表/结构/综合）
public/js/chat.js       对话（关键词 RAG top6 + SSE + 页码引用）
plugin/          DSH 插件包 dsh-litbench
tools/           打包、自测、端到端脚本（非运行依赖）
```

改动 PDF 相关逻辑时注意：`reader.js` 由 `_rA.js` / `_rB.js` / `_rC.js` 三段拼接，跑 `npm run build:reader` 生成。这是为了让单文件足够大又能分段维护的妥协。
